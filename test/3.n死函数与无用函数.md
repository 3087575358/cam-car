# 死函数bmp_handler(变体已经被拿去在stream中负责jpeg图传)
```cpp
static esp_err_t bmp_handler(httpd_req_t *req)
{
    camera_fb_t *fb = NULL;
    fb = esp_camera_fb_get();

    esp_err_t res = ESP_OK;

    httpd_resp_set_type(req, "image/x-windows-bmp");
    httpd_resp_set_hdr(req, "Content-Disposition", "inline; filename=capture.bmp");
    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    char ts[32];
    snprintf(ts, 32, "%ld.%06ld", fb->timestamp.tv_sec, fb->timestamp.tv_usec);
    httpd_resp_set_hdr(req, "X-Timestamp", (const char *)ts);

    uint8_t * buf = NULL;
    size_t buf_len = 0;
    bool converted = frame2bmp(fb, &buf, &buf_len);
    //把bmp文件转换成数据流, 存于缓存buf中
    esp_camera_fb_return(fb);

    res = httpd_resp_send(req, (const char *)buf, buf_len);
    //发送转换成功的buf数据流报文
    free(buf);
    uint64_t fr_end = esp_timer_get_time();
    // 如果这fr_end没有设置,下面的日志一样会继续记载,数据哪里来?
    log_i("BMP: %llums, %uB", (uint64_t)((fr_end - fr_start) / 1000), buf_len);
    //数据发送成功写入日志
    return res;
}
```

# capture的译名误会
这里的capture更类似于seize, 而非是take a picture
本质是通过停止图像传输的瞬间, 保留客户端显示的最后一帧图像
然后通过浏览器内置的download功能让客户端有"保存功能"

# 这并非是我们想要的功能
我们需要的功能
在图传保持的情况下
是3*2的6种模式

保存内容选择
1. 抓拍内容-jpg(这个好说, 双端都有现成代码)
2. 视频内容-avi(这涉及到一个问题就是mjpeg的流式数据stream有对应的格式吗?有的avi格式,不过转换工具和代码要花上一段时间了)

保存位置选择
1. 服务器本地保存(如果有PSRAM),客户端不保存
2. 服务器本地不保存,客户端保存(当未检测到PSRAM时自动执行此策略并在客户端的html页面hide 对应的switch-box)
3. 服务器本地保存(如果有PSRAM),客户端保存
(客户端的保存要怎么保持对窗口数据的持续截获,并在结束录像时选择保存地址,要写js脚本)

所以接下来的章节我们解决两个问题
esp32cam的本地保存
js脚本监听抓取视频内容
