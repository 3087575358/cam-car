# 2.2 回调设计模式：指令→查表→执行

> 不管前端 JS、后端 C++/Go、还是脚本 Lua/Bash，  
> 物联网全栈的核心逻辑永远是：**指令接收 → 查表解析 → 回调执行**。  
> 语言只是语法糖，设计模式是相通的。


# 基本示例
```cpp
// handlers/cmd_handler.cpp
#include <unordered_map>
#include <functional>

using CmdHandler = std::function<int(sensor_t*, int)>;

const std::unordered_map<std::string, CmdHandler> cmd_map = {
    {"framesize", [](sensor_t* s, int v){ return s->set_framesize(s, (framesize_t)v); }},
    {"quality",   [](sensor_t* s, int v){ return s->set_quality(s, v); }},
    {"contrast",  [](sensor_t* s, int v){ return s->set_contrast(s, v); }},
    // ... 你的所有命令
};

// cmd_handler的编译
auto it = cmd_map.find(variable);
if (it != cmd_map.end()) {
    res = it->second(s, val);
} else {
    log_w("Unknown command: %s", variable);
    res = -1;
}
```

# 什么是std::unordered_map
std::unordered_map 是C++标准库里的哈希表数据结构。你可以把它理解为：\
一个"字典"或"查表本"：左边是关键词（key），右边是对应的内容（value），通过关键词能在常数时间 O(1) 内快速找到内容。
```cpp
std::unordered_map<std::string, CmdHandler> cmd_map
//           ↑key的类型是string    ↑value的类型是CmdHandler
```
并定义返回值类型
```cpp
using CmdHandler = std::function<int(sensor_t*, int)>;
//     ↑类型别名                    ↑这是一个"可调用对象"的类型
```
哈希表方法处理字符串命令\
听起来可能比较高级,不过实际上也是注册表查表+函数回调的基本方法\
只不过用的是c++的语法

其逻辑就是类似于注册一个cmd_map哈希表
并且在得到对应字符串命令时, ```auto it = cmd_map.find(variable);```自动在哈希表中寻找对应的参数值变量, 执行对应的操作```例如return s->set_framesize(s, (framesize_t)v); ```

有没有发现他的逻辑和js还有ros的回调的逻辑还有语法极其相似\
这玩意就是最初的回调逻辑的完全体\
绝大部分网联与单片机操作操作的函数逻辑是:**指令接收->指令解析->指令执行**\
之后,这一套根据指令与参数传递,直接调用回调函数逻辑就屡试不爽\
不过是语言变化,语法小改\

4. 在微服务网关常用的GO语言中
```go
var registry = map[string]func(int) error{
	"motor_left":  func(v int) error { return motorSetPWM(0, v) },
	"motor_right": func(v int) error { return motorSetPWM(1, v) },
}

func execute(cmd string, val int) error {
	if fn, ok := registry[cmd]; ok {
		return fn(val)  // 查表命中 → 执行回调
	}
	return fmt.Errorf("unknown: %s", cmd)
}
```
5. 经常用于游戏脚本编写的Lua语言中
```Lua
local registry = {
	motor_left  = function(v) motor.setPWM(0, v) end,
	motor_right = function(v) motor.setPWM(1, v) end,
}

function execute(cmd, val)
	local fn = registry[cmd]
	return fn and fn(val) or print("unknown: "..cmd)  -- 查表 → 执行或报错
end
```

```cpp
const std::unordered_map<std::string, CmdHandler> cmd_map = {
    {
        "字符串1,格式对应std::string", 
        [对应TCP\IP网络链接中的网络状态,这里也可以回传一些外部变量来标记系统的运行状态或指令层级等等, 不过咱们的小项目不需要用到这个]
        (用于传入接下来的回调函数中的参数们)
        {实际的执行函数}
    },
};
```
写成
那么就有了
```cpp
const std::unordered_map<std::string, CmdHandler> cmd_map = {
    {"framesize", [](sensor_t* s, int v){ return s->set_framesize(s, (framesize_t)v); }},
    {"quality",   [](sensor_t* s, int v){ return s->set_quality(s, v); }},
    {"contrast",  [](sensor_t* s, int v){ return s->set_contrast(s, v); }},
    // ... 你的所有命令
};
```
然后记得在处理函数里面执行
```cpp
// ========== cmd_handler 统一管 HTTP ==========
static esp_err_t cmd_handler(httpd_req_t *req)
{
    // ... 解析 variable 和 val ...
    
    sensor_t *s = esp_camera_sensor_get();
    int sensor_res = -1;  // 默认未知命令/失败

    auto it = cmd_map.find(variable);
    if (it != cmd_map.end()) {
        sensor_res = it->second(s, val);  // 找到了，执行传感器参数返回
    } else {
        log_w("Unknown command: %s", variable);
        // sensor_res 保持 -1
    }

    // 统一映射：业务结果 → HTTP 响应
    if (sensor_res < 0) {
        return httpd_resp_send_500(req);
    }

    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    return httpd_resp_send(req, NULL, 0);
}
```


这里讲的这个方法在文件设计方面更简便,不用想注册表方法一样还专门去设置头文件\
但是代价也是很明显的: 并不是所有初学者都能看懂哈希表!\
所以综合考虑,如果后面你的代码单纯拿来给小团队用的话, 注册表方法绝对是不二之选\

当然也不是说这个方法就不行\
其一,基本的注册表方法算法比较慢, 哈希表由于其特殊的查表方法,在对应命令比较多的时候,速度不是一般的快
其二,哈希表方法同样用的是**指令接收(->指令解析->)指令执行**, 后期如果能直接写一个专门增删改哈希表的脚本,对应的SDK以及开放给用户端的API接口的编写使用起来会方便得多(只需要进入cmd_map修改,不需要去找头文件改#define,更不需要去碰cmd_handler里面的strcmp)

最后,也是最重要的,进一步让读这篇文档的读者深入了解**指令接收->指令解析->指令执行**的回调逻辑
