# 写在前面
现在绝大多数的物联网视频传输开发使用的是\
```<video> + H264/WebRTC```, 以```.m3u8```为代表格式的
.H264/.H265的编码格式来实现\
较低带宽下的高码率视频传输功能

但我们的esp32cam并没有专门的H264编码器\
使用的是最简单的MJEPG逻辑(字如其名,传输逻辑就是Multiplied JEPG,一帧一帧的传输jpg图像, 来实现视频效果)\
这就导致了: \
即使抽到一台体制特别好的esp32cam(RF射频带宽:802.11 b/g/n，实际吞吐 ~10-20 Mbps)\
在最高分辨率UXGA (1600x1200)与最大画面质量(Quality=64)的加持下\
```UXGA @ 15fps ≈ 150KB × 15 = 2250KB/s ≈ 18 Mbps```\
我们的画面依然很难突破15帧

所以如果你想要的是类似RC遥控车的图传效果,现在立马出门左转,查看\
**ESP32-P4 + OV5647**, 原生H264硬件编码器, 500w摄像头并自带双轴防抖\
又或者找传统的**STM32+NRF24L01+OV7670**开发流程, 这我就不说了,妥妥的企业及项目

所以如果你是想借由此作为**ESP32-P4 + OV5647**项目的学习跳板(作者就是这样,估计你看到这篇文章的时候作者可能已经在开发基于ESP32-P4的cam小车.ver3项目了)
又或者实现一个不需要多高分辨率的最基础的状况识别功能
那么这个项目以及文章接下来的内容对你肯定是有裨益的

但是如果你是奔着.H264/.H265的编码格式实现图传效果,以及高分辨率的企业及项目来找东西的话,那只能说你要是有时间,也可以看看MJEPG的实现路径(说不定以后能用得上不是?)

## html读取
```html
<section id="buttons">
    <button id="get-still">画面保持</button>
    <button id="toggle-stream">实时图像数据流传输</button>
</section>
<figure>
    <div id="stream-container" class="image-container hidden">
        <a id="save-still" href="#" class="button save" download="capture.jpg">Save</a>
        <div class="close" id="close-stream">×</div>
        <img id="stream" src="" crossorigin>
    </div>
</figure>
```
可以看到负责数据读取的按钮:
1. **toggle-stream**:负责转换数据流的开关状态
2. **get-still**:再不关闭数据流的情况下保持画面
3. **save-still**:负责远程保存图片(注意其格式并不是button而是link,因为用到了远程保存,需要使用浏览器内置的保存功能,本质是"链接转浏览器固件"的本地操作)
4. **close-stream**:额外加的关闭数据流传输功能(依旧尼玛的留坑,草泥马的读取功能不好好用button在这写个div,生怕自己代码让人家读懂了)
      
负责传输图片的img功能
· 这个值得好好说道说道: img作为一个单独的类别对象, 按照正常的逻辑来说只需要改id留给后端的js,以及修改src来确认图片源就行了\
· 但这里的作者加了一个**crossorigin** ,先简单说下为什么要加这个东西:\
    为了视频传输过程中的流畅,我们使用了\
    http://192.168.1.100:81 来作为图传的专属端口\
    原来默认的http://192.168.1.100:80 则是依然作为其他所有命令的传输通道\
    而我们的```<a id="save-still" href="#" class="button save" download="capture.jpg">Save</a>```是```port=80```的uri大类里面的发出的命令\
    在服务器看来,这实际上是一次跨域请求: 你一个来自80端口的命令,凭什么去81端口获取下载数据?

尽管他俩就在一台单片机上运行,但是端口不同我就认定你不是正常请求,"你又没在我注册表里,我咋知道你是不是黑客?"(这个难搞的历史问题要追溯到<a href="https://www.descope.com/blog/post/cors-errors">CORS 很容易被绕过...你可能会想知道它为什么存在</a>)\
总而言之言而总之, 为了保证服务器的运行速率同时兼容以前的CORS写一部分,我们需要加一个crossorigin来给他一个"Access-Control-Allow-Origin: *"(access control from all origin is allowed)的"直达门"

简单来说就是
```
通过streamButton.onclick时,检测streamButton.innerHTML的状态\
    如果原来时关闭的状态:
        就切到打开的状态
        并且修改streamButton.innerHTML为'停止图像传输'(之后这个按钮就用来关闭传输);
    如果原来是打开的状态
        就切换到关闭的状态
        并且修改streamButton.innerHTML为'实时图像数据流传输'(之后这个按钮就用来打开传输);

当stillButton.onclick触发时
    停止图像传输
    并且把画面切换为按钮按钮按下(esp32接收到按钮按下的信息之后)的瞬间的图像
    // view.src = `${baseHost}/capture?_cb=${Date.now()}`
```

    const saveButton = document.getElementById('save-still')
