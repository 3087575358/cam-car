# 代码处理的第一步:化简——留下核心功能
咱们的小车暂时只需要图传,所以首先明确
1. 咱们不需要 **人脸识别功能**,所以所有有关```FACE_RECOGNITION```的```#if 和 #ifdef```全部删除
2. 其次就是我们这里只对硬件的核心操作负责,而不关心网络层连接错误导致的问题,所以
有关网络错误导致的```errorcode=500,errorcode=404,等等```网络错误返回码的部分, 统一删除
3. 我们只关心线性的执行流程,以及对应的主要函数,而不需要设置繁杂的固件错误日志\
代码固件执行失败导致的```ESP_FAIL```的返回内容, 一样删掉
4. 在非调试模式下```ARDUHAL_LOG_LEVEL < ARDUHAL_LOG_LEVEL_INFO```,\
平滑器```ra_filter_run```不会启动,所以有关语句一起删除

```cpp
            _jpg_buf = NULL;

                 avg_frame_time, 1000.0 / avg_frame_time);
    }

#if CONFIG_LED_ILLUMINATOR_ENABLED
    isStreaming = false;
    enable_led(false);
#endif
```

# 时间轴 与 相对时间(及其命名规律)
    作者之前有写过一个matlab模拟多智能体运动的论文代码复现
    里面的总时间设计可能是20s,30s
    但是对应每一次只能提的位置更新的间隔时间不可能以s秒来作为计算单位
    通常是0.001s也就是1ms,那么我就称这个1ms为我的步长
    相对的,这种单位设置的方式在许多详谬中都很常见:
    ```
        我的时间计数器可能是32678(也就是我的程序的循环次数k=32678)
        但如果我对应的循环一次设置的步长为1ms
        那次是的时间就应该是t=32678/T=32.678s
    ```
在此基础上

# 内存管理上的一个小风险

首先明确的一点是,如果你的固件读取出来的格式就是jpg格式,那么你完全没有必要
```cpp
定义数据暂存buf
size_t _jpg_buf_len = 0;
uint8_t *_jpg_buf = NULL;
并强制数据转换
fb->format != PIXFORMAT_JPEG
```
而是应该直接
```cpp
while(true){
    if (res == ESP_OK)
    {
        res = httpd_resp_send_chunk(req, _STREAM_BOUNDARY, strlen(_STREAM_BOUNDARY));
        size_t hlen = snprintf((char *)part_buf, 128, _STREAM_PART, fb->len, fb->timestamp.tv_sec, fb->timestamp.tv_usec);
        res = httpd_resp_send_chunk(req, (const char *)part_buf, hlen);
        res = httpd_resp_send_chunk(req, (const char *)fb->buf, fb->len);
    }
}
// 可能涉及到出具类型转换的一些小问题,像原来的函数一样直接强行转就可以了
```
那你就要问了: 原函数写这一堆buf拿来干甚? 这不是空耗运行内存吗?

    如果说我全程都一定使用的有且只有一种格式也就是jpeg
    我完全可以这么做
    问题就在于狗操的esp32cam为了宣传效果,写了一堆人脸识别的功能
    只要你稍微有点opencv的基础,
    就知道任何人工智能的图片数据识别一定是以RGB三原色为基础进行的
    对应的
    原函数中的一大堆人脸识别功能, 就是需要RGB格式作为基础的
    但是我们的图像传输可是使用的jpeg格式
    那这个数据转换怎么办呢?

所以你可以看到他用了一堆及其别扭的buf和#if, 丑陋的无以复加

而且还用到了free这个函数来进行释放操作\
一般在有规范的内存池管理的数据库下,这没什么问题\
但是tm这是一个运行内存只有4MB的单片机. 一大堆的暂存数据挨着彼此放在这\
**free这玩意执行的不是软件DMA层面的数据管理模式**\
**而是根据硬件块的NAND分区来标记可用状态的**\
你的free要是一不小心发现这一块NAND的head状态没有标记(但是实际上这块NAND里面暂时存放了一堆数据)\

# 另外一些规范化的小问题
至于原来的语句为什么每一次
```httpd_resp_send_chunk```
和
```httpd_resp_send```
的时候都要问下```ESP_OK```的状态,是因为网络连接的不稳定性
一旦网络连接断了,可以及时的直接返回避免返回一堆无意义的乱码或者跳过内存清楚操作导致爆内存

```cpp
\\ code_version_0.1.8
static esp_err_t stream_handler(httpd_req_t *req)
{
    camera_fb_t *fb = NULL;
    esp_err_t res = ESP_OK;
    char *part_buf[128];

    static int64_t origin_frame_time = 0;
    if (!origin_frame_time)
    {
        origin_frame_time = esp_timer_get_time();
    }

    httpd_resp_set_type(req, _STREAM_CONTENT_TYPE);
    httpd_resp_set_hdr(req, "Access-Control-Allow-Origin", "*");
    httpd_resp_set_hdr(req, "X-Framerate", "60");

    while (ESP_OK){
        fb = esp_camera_fb_get();// 记得确保esp_camera的原始格式设置一定要是jpeg格式
        size_t hlen = snprintf((char *)part_buf, 128, _STREAM_PART, fb->len, fb->timestamp.tv_sec, fb->timestamp.tv_usec);

        httpd_resp_send_chunk(req, _STREAM_BOUNDARY, strlen(_STREAM_BOUNDARY));
        httpd_resp_send_chunk(req, (const char *)part_buf, hlen);
        httpd_resp_send_chunk(req, (const char *)fb->buf, fb->len);

        int64_t current_frame_time = esp_timer_get_time();
        int64_t capture_time = current_frame_time - origin_frame_time;
        capture_time /= 1000;   //根据单位来选择是否要除

        log_i("MJPG: %uB %ums (%.1ffps)",
                 (uint32_t)(fb->len),
                 (uint32_t)capture_time, 1000.0 / (uint32_t)capture_time);
    }
    return 1;
}
```
