## 1. 误导化函数名的修改——重命名
某些函数的命名是在不知所云,语言的歧义太大(谁说英语的语言熵低的), 作者本人过上几个月都不一定能记得起来这一坨是干嘛的\
鉴于此,这里对几个函数进行重命名
我们之后的函数也应该在回答了下面的问题之后,以一定的下面的命名规则进行定义
1. 读取了哪些数据
2. 把这些数据用在了那些参数传递上面
3. 是否发送了这些数据
4. 如果是客户端,是否同步更新了UI显示
5. **有没有把这些数据发送给服务器**(这是最重要的问题)
6. 是否在其他用户或者服务端有相似操作,**所以命名定义需要特别注明这个操作进行的设备与在网络链接中的位置**
7. 这些问题是否需要在函数内部加上注释

### 1.1 ~~updatevalue~~,应该叫update_value_display_on_client_side
这个函数只会（根据服务器读取到的数据）更新本地的数值显示，而不会发送修改命令
```js
  // 更新 UI 并同步到服务器
  // 这个函数的名字不叫updateValue，应该叫update_value_display_on_client_side
  // 他不会修改esp32的配置值，而是根据传入的value参数来更新UI显示状态
  const updateValue = (el, value, updateRemote) => {
    updateRemote = updateRemote == null ? true : updateRemote
    let initialValue
    if (el.type === 'checkbox') {
      initialValue = el.checked
      value = !!value
      el.checked = value
    } else {
      initialValue = el.value
      el.value = value
    }

    //根据初始值和当前值的对比，决定是否需要发送更新请求到服务器：是否需要进行UI联动显示/隐藏等操作
    if (updateRemote && initialValue !== value) {
      updateConfig(el);
    } 
  }
```

### 1.2 ~~updateConfig~~,应该叫read_And_Send_Control_to_server
```js
  // 发送配置到服务器
  // read the element input type and its value of type-name
  // then send the config to server esp32cam 
  // esp32cam will update its varied variable and varied value
  // 所以不多说,应该改名为read_And_Send_Control
  function updateConfig (el) {
    let value
    switch (el.type) {
      case 'checkbox':
        value = el.checked ? 1 : 0
        break
      case 'range':
      case 'select-one':
        value = el.value
        break
      case 'button':
      case 'submit':
        value = '1'
        break
      default:
        return
        //注意js中case语法的顺延性
    }

    const query = `${baseHost}/control?var=${el.id}&val=${value}`

    fetch(query)
      .then(response => {
        console.log(`request to ${query} finished, status: ${response.status}`)
      })
  }
```

## 枚举 + 映射表方法修改大段重复的if-else语句——代码结构规范化
简单来说就是把***app_httpd.cpp***文件中查找命令字符的if-else语句换成switch-case语句\
可读性更好,维护方便,而且还能防止过多的if-else撑爆PSRAM\
不过由于switch-case的语法要求case标签必须是编译时常量整数表达式(必须是数字,而不能是string或者char*)\
所以必须要加个头文件basic_setiing_config.h作为映射表\
然后case读取映射表中的常数来进行函数操作\

### 这个需要额外添加一个basic_setiing_config.h文件,
或者在原来就引用的文件中加入线面的内容,但是不建议,修改人家的头文件万一你的项目被以后谁拿去粘贴,同一个头文件人家发现你项目运行不起来就很难受了
```cpp
// config.h
typedef enum {
    VAR_FRAME_SIZE,
    VAR_QUALITY,
    VAR_CONTRAST,
    VAR_BRIGHTNESS,
    // ... 其他变量
    VAR_UNKNOWN
} var_id_t;

// 字符串到枚举的查找表（只读，存于Flash）
typedef struct {
    const char *name;
    var_id_t    id;
} var_map_t;

static const var_map_t var_map[] = {
    {"framesize",      VAR_FRAME_SIZE},
    {"quality",        VAR_QUALITY},
    {"contrast",       VAR_CONTRAST},
    {"brightness",     VAR_BRIGHTNESS},
    {"saturation",     VAR_SATURATION},
    {"gainceiling",    VAR_GAINCEILING},
    {"colorbar",       VAR_COLORBAR},
    {"awb",            VAR_AWB},
    {"agc",            VAR_AGC},
    {"aec",            VAR_AEC},
    {"hmirror",        VAR_HMIRROR},
    {"vflip",          VAR_VFLIP},
    {"awb_gain",       VAR_AWB_GAIN},
    {"agc_gain",       VAR_AGC_GAIN},
    {"aec_value",      VAR_AEC_VALUE},
    {"aec2",           VAR_AEC2},
    {"dcw",            VAR_DCW},
    {"bpc",            VAR_BPC},
    {"wpc",            VAR_WPC},
    {"raw_gma",        VAR_RAW_GMA},
    {"lenc",           VAR_LENC},
    {"special_effect", VAR_SPECIAL_EFFECT},
    {"wb_mode",        VAR_WB_MODE},
    {"ae_level",       VAR_AE_LEVEL},
#if CONFIG_LED_ILLUMINATOR_ENABLED
    {"led_intensity",  VAR_LED_INTENSITY},
#endif
};

// 查找函数（线性查找，小表足够快）
static inline var_id_t get_var_id(const char *name) {
    for (int i = 0; i < sizeof(var_map)/sizeof(var_map[0]); i++) {
        if (!strcmp(var_map[i].name, name))
            return var_map[i].id;
    }
    return VAR_UNKNOWN;
}
```
